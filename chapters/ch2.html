Token 与 Embedding

语言模型"读"文本的方式和人完全不同。它不是逐字读，而是先把文本切成token，再把每个 token 映射成高维空间里的一个坐标向量（embedding）。理解这两个概念，你才能真正明白 LLM 擅长什么、为何在字符操作上会出错、以及"语义相似"究竟是怎么计算出来的。
🔪
Token：切块读文

文本被切成一个个子词单元。"strawberry" 不是 10 个字符，而是 2 个 token：["straw", "berry"]。这个切法从根本上影响模型的字符操作能力。

📐
Embedding：语义坐标

每个 token 被映射成一个高维向量（如 1536 维）。意思相近的词，坐标离得近；语义运算成为可能：国王 − 男人 + 女人 ≈ 王后。

💰
Token = 计费单位

GPT-4 按 token 计费，上下文窗口也以 token 为单位（如 128k）。中文 1 个汉字约 1.5 token；英文 1 个单词约 1-2 token。

🧩
两者的关系

进入 Transformer 的第一步就是 token → embedding：把离散的词块翻译成模型可以做数学运算的连续向量。

模型不是逐字符读文本——它先用分词器（tokenizer）把文本切成一个个token，再处理这些 token 序列。BPE（字节对编码）是 GPT 系列的分词算法。

BPE（字节对编码）：分词器如何被"训练"出来

BPE 是一个纯数据驱动的算法，它的词表不是人工规定的，而是从海量语料里统计出来的。步骤如下：

① 初始：把所有文本拆成单个字节（字符）。
词表里只有字符：a, b, c, …, z, 0-9, 空格, 标点……

② 反复合并最频繁的相邻字节对。
扫描整个训练语料，找出出现次数最多的两个相邻单元，把它们合并成一个新 token 加入词表。例如语料里 "th" 极为频繁，合并后 "th" 成为一个独立 token。然后继续：下一次最频繁的是 "the"，再合并……

③ 重复直到词表达到目标大小（GPT-4 约 10 万个 token）。

这就解释了 "strawberry" 为什么切成 ["straw", "berry"]：
在训练语料（互联网文本）里，"straw" 和 "berry" 各自作为高频组合被合并成了独立 token。但 "strawberry" 整体不够频繁，所以分词器在看到它时，匹配到最长的已知 token "straw"，再匹配 "berry"，就切开了。模型拿到的是两个原子单元 straw 和 berry——它需要"打开"这两个 token、在字符级做推理才能数字母。而 Transformer 的注意力机制是在 token 级操作的，字符级推理需要额外的思维步骤，这正是出错的根源。

三个实际影响：
①字符级操作天生困难——数字母、押韵、反转字符串、拼写纠错，模型都要"反向解码"token 才能做，容易出错。
②上下文窗口以 token 计——GPT-4 的 128k "上下文长度"指的是 128,000 个 token，不是字符。英文约 1 词 ≈ 1.3 token，中文约 1 汉字 ≈ 1.5 token。一篇 1 万字的中文文章约消耗 15,000 token。
③计费以 token 计——API 按输入+输出 token 数计费，理解 token 密度帮助你估算成本。

Embedding：语义坐标

每个 token 进入模型的第一步，是被映射成一个高维向量（embedding）。这个向量是模型理解"这个词是什么意思、和其他词什么关系"的语言。
📐 Embedding：词变坐标
把每个 token 编码成高维空间中的一个点（向量）。意思相近的词，坐标离得近；意思相反的词，坐标离得远。
类比：城市地图
把所有词放进一张地图：猫和狗住得很近（都是宠物），猫和苹果住得很远。地图上的坐标，就是 embedding 向量。你可以测量两个词的距离，也可以做方向运算：从"法国"走向"英国"的方向向量，大致也能从"巴黎"走向"伦敦"。
关键词：token → 高维向量 → 语义相似 = 空间相近 → 支持向量运算
Embedding 的数学基础与学习方式

向量维度：一个 embedding 向量有几百到几千个维度（text-embedding-ada-002 是 1536 维；GPT-4 内部 embedding 更大）。每个维度没有预先定义的含义——它们是模型从训练数据里自动学出来的，某个维度可能隐约对应"是否是动物"或"情感正负性"，但没有人工标注。

怎么学出来的：以 Word2Vec（Skip-gram 版本）为例——把词放进句子里，让模型预测"这个词的周围应该出现哪些词"。一个词的邻居信息就是它的语义信息。训练目标是：出现在相似上下文中的词，embedding 要接近；上下文完全不同的词，embedding 要远离。GloVe 则利用全局共现统计矩阵来学习。现代大模型用的是预测被掩码的 token（BERT）或预测下一个 token（GPT），embedding 作为模型底层参数的一部分一起被优化。

余弦相似度：衡量两个向量"方向是否一致"的指标，而不是距离。公式：
cos(a, b) = (a · b) / (|a| × |b|)
取值 −1 到 1：值越接近 1，方向越一致 = 语义越相近；值接近 0，不相关；值接近 −1，语义相反（如 good / bad）。用余弦而不用欧氏距离，是因为两个词的 embedding 模长（范数）可能因词频不同而差异很大，但方向才是语义的载体。

经典语义运算（向量算术）：
国王 − 男人 + 女人 ≈ 王后（king − man + woman ≈ queen）
巴黎 − 法国 + 德国 ≈ 柏林（paris − france + germany ≈ berlin）

这不是刻意编程进去的——它是从大量文本共现模式中涌现出来的几何关系。"国王"和"王后"的差异方向，与"男人"和"女人"的差异方向是相近的，因为这两对词在大量文本里的使用关系极为相似。

Token 与 Embedding 的关系：进入 Transformer 的第一步，就是把 token ID（整数）通过一个 Embedding 查找表，转换成对应的高维向量。模型此后所有的注意力计算、前馈层运算，都是在这些向量上进行的。文本转向量，就是语言变成数学的入口。
Word2Vec 原始论文：Efficient Estimation of Word Representations（Mikolov et al., 2013） GloVe：Global Vectors for Word Representation（Stanford NLP） TensorFlow Embedding Projector：交互式 3D 词向量可视化（在线工具）

⚡ 反直觉发现：反义词在 embedding 里其实很接近

试试把 good 和 bad 输入相似度计算——结果约 80%，不是负数。
为什么？因为 embedding 是从大量文本的共现统计中学出来的，而不是从"语义对立性"学出来的。good 和 bad 出现在极其相似的上下文里： "this movie is good/bad"、"it made me feel good/bad"、"the news is good/bad"…… 同样的句式、同样的前后词，所以两者的向量方向非常接近。

这是 embedding 的一个重要局限：它编码的是"分布相似性"（distributional similarity），不是"含义对立性"。要区分正负情感，需要专门设计带情感标注的 embedding，或者在训练任务里加入情感分类目标。

知识自测

1. GPT 系列使用的分词算法叫什么，它的核心思路是什么？
按照字典中的单词边界切分，所以 "strawberry" 是一个 token。
BPE（字节对编码）：从字符出发，反复合并训练语料中最频繁的相邻单元，构建子词词表。
把每个字符单独作为 token，这样模型就能精确处理字母级操作。
由语言学家手工制定分词规则，确保每个词义单元对应一个 token。
2. 衡量两个 embedding 向量"语义相近程度"，通常用哪种度量，为什么不直接用欧氏距离？
L2 欧氏距离，因为距离越小两点越近，直觉最清晰。
余弦相似度，因为它只衡量向量的方向而非长度，能排除词频等因素造成的模长差异。
点积（dot product），因为和余弦等价。
曼哈顿距离，因为对高维空间更鲁棒。
3. 为什么语言模型在"数 strawberry 里有几个 r"这类任务上容易出错？
模型没有长期记忆，无法记住之前数过哪些字母。
模型会产生幻觉，所以随机给出错误答案。
分词器把 "strawberry" 切成 ["straw","berry"] 两个 token，字符级操作需要跨 token 推理，模型不擅长这类反向解码。
模型对英文字母识别能力弱，换成中文就不会出错。

本章小结

🔪
Token 是原子单元

模型的输入不是字符序列，而是 token 序列。BPE 算法从语料统计中学出子词词表。"strawberry" → ["straw","berry"]，字符级操作因此变难。

💰
Token 是计量单位

上下文窗口（128k）、API 费用、输入输出长度，全部以 token 计。中文约 1 汉字 = 1.5 token；英文约 1 词 = 1.3 token。

📐
Embedding 是语义坐标

每个 token 被映射成高维向量；方向编码语义；余弦相似度衡量"近不近"；语义运算（国王 − 男人 + 女人 ≈ 王后）从大量文本中涌现。

🧩
Token → Embedding = 语言到数学

进入 Transformer 的第一步就是 token ID → embedding 向量。此后所有注意力、前馈层运算都在向量空间中进行。这是语言变成数学的入口。

一句话带走：语言模型读文本的方式是"按块切"（token），理解语义的方式是"变坐标"（embedding）。理解这两步，你就掌握了 LLM 输入端最核心的数据表示机制。
📖

词汇表

Token
语言模型处理文本的最小单位：介于字符与词之间的子词块，由 BPE 算法切分。1000 个英文单词 ≈ 750 token；1000 个汉字 ≈ 1300 token。
BPE（字节对编码）
Byte Pair Encoding。从单字符出发，反复合并语料中出现最频繁的相邻字节对，迭代构建子词词表的算法。GPT 系列分词器的核心算法。
子词（Subword）
介于字符和完整词之间的文本单元。"playing" 可被切为 "play" + "ing"。子词切分在词汇量和泛化能力之间取得平衡，是现代 NLP 的主流策略。
Embedding（嵌入）
将离散的 token 映射到连续高维向量空间的表示方法。语义相似的 token 在向量空间中距离近；训练出的向量支持语义算术运算。
向量（Vector）
由一组数字组成的有序列表，表示高维空间中的一个方向或位置。Embedding 就是用高维向量（如 1536 维）来表示每个 token 的语义。
余弦相似度
衡量两个向量方向是否相近的指标，取值 −1 到 1。值越接近 1，语义越相近。不受向量长度影响，是 NLP 中衡量语义相似性的标准度量。
