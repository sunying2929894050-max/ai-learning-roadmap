①

提示词工程（Prompt Engineering）

提示词是和大模型交互的唯一接口。写好提示词不是"技巧"，而是系统性的工程思维。

①
角色 + 任务 + 约束 + 格式（RTCF 框架）

好的提示词包含四个要素：你是谁（角色）、做什么（任务）、不能做什么（约束）、怎么输出（格式）。

# 差的提示词
"帮我写产品描述"

# 好的提示词（RTCF）
"""你是一位擅长转化率优化的电商文案专家（角色）。
为一款无线蓝牙耳机写一段产品描述（任务）。
不要夸大功能，不要使用专业术语（约束）。
格式：3句话，第1句突出核心卖点，第2句场景化使用体验，
第3句行动号召。（格式）"""
②
少样本提示（Few-Shot Prompting）

给模型几个例子，让它理解你想要的输出模式。对于格式固定的任务（数据提取、分类、格式转换）效果显著。

"""从客户评论中提取情感和关键问题。

例1：
评论：产品质量很好，但快递太慢了
情感：正面
问题：物流速度

例2：
评论：客服态度恶劣，退款困难
情感：负面
问题：客服、售后

请处理：{用户评论}"""
③
思维链（Chain-of-Thought, CoT）

对于需要推理的问题，让模型一步步思考再给出答案。比直接要答案准确率高很多。

"请一步步分析这道题，列出推理过程，最后给出答案。"
# 或者更简单：
"Let's think step by step."  # 这一句话对复杂推理有显著提升
技术适用场景核心作用
Zero-shot简单明确的任务直接描述任务，无需示例
Few-shot格式固定、模式重复的任务给例子让模型理解输出格式
Chain-of-Thought数学推理、逻辑分析、多步骤问题引导模型逐步推理，减少直觉性错误
System Prompt持续性对话场景设定模型的身份、行为边界和约束
②

大模型 API 调用

不必自己训练大模型。通过 API 调用已有的大模型（Claude、GPT 等），是绝大多数 AI 应用的实际做法。

▸ 基础 API 调用结构
import anthropic  # pip install anthropic

client = anthropic.Anthropic(api_key="your_api_key")

message = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    system="你是一位专业的数据分析师，用简洁清晰的语言回答问题。",
    messages=[
        {"role": "user", "content": "请分析这组销售数据的趋势：[100, 120, 115, 140, 165, 180]"}
    ]
)

print(message.content[0].text)
▸ 结构化输出（让 AI 返回可解析的 JSON）
import json

prompt = """分析以下产品评论，返回 JSON 格式：
{"sentiment": "正面/负面/中性", "score": 1-5, "key_issues": ["问题1", "问题2"]}

评论：这款耳机音质不错，但佩戴三小时后耳朵有些不舒服，包装也比较简陋。"""

response = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=512,
    messages=[{"role": "user", "content": prompt}]
)

result = json.loads(response.content[0].text)
print(result["sentiment"])     # 中性
print(result["key_issues"])    # ["佩戴舒适度", "包装质量"]
API 调用的核心经济学：大模型按 token 计费（输入 + 输出）。好的提示词不只是为了效果，也是为了效率——清晰简洁的提示词减少 token 消耗，降低成本。
③

RAG：让大模型回答你的私有知识库

大模型只知道训练数据截止前的知识，不知道你公司的内部文档、最新数据、私有资料。RAG（检索增强生成）解决这个问题。

①
建立向量数据库

把你的文档（PDF、Word、网页）切分成小段（chunk），用"嵌入模型（Embedding Model）"把每段文字转换成向量，存入向量数据库（如 Chroma、Pinecone）。

嵌入向量：把文字的语义压缩成一串数字（如 1536维向量）。语义相近的文字，向量也相近——这是"语义搜索"的基础。
②
用户提问时，语义检索相关文档

把用户的问题也转成向量，在数据库中找最相似的几段文档（余弦相似度）。

③
把检索到的文档塞入提示词，让大模型回答

把检索到的相关文档片段作为上下文，连同用户问题一起发给大模型，让模型"参考这些资料"回答。

from langchain.vectorstores import Chroma
from langchain.embeddings import OpenAIEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter

# ① 切分文档
with open("company_handbook.txt") as f:
    text = f.read()

splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_text(text)

# ② 建立向量数据库
db = Chroma.from_texts(chunks, OpenAIEmbeddings())

# ③ 检索 + 生成
def rag_answer(question):
    # 检索最相关的 3 段文档
    relevant_docs = db.similarity_search(question, k=3)
    context = "\n\n".join([doc.page_content for doc in relevant_docs])

    prompt = f"""请根据以下公司手册内容回答问题。如果手册中没有相关信息，请明确说明。

相关内容：
{context}

问题：{question}"""

    # 调用大模型生成答案
    response = client.messages.create(
        model="claude-opus-4-8", max_tokens=1024,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.content[0].text

print(rag_answer("公司的年假政策是什么？"))
类比：开卷考试
RAG 就像把闭卷考试改成开卷——大模型考试前（推理时）可以翻阅你指定的资料书（知识库），然后综合作答。它的优势是能引用你的私有、最新的知识；局限是"资料书"里没有的内容它仍然不知道。
④

模型部署：从本地到生产环境

训练好的模型要变成别人可以使用的服务，需要部署——封装成 API，让任何人通过 HTTP 请求使用。

◆ 用 FastAPI 封装模型为 REST API
from fastapi import FastAPI
from pydantic import BaseModel
import torch
import pickle

app = FastAPI()

# 加载训练好的模型
with open("model.pkl", "rb") as f:
    model = pickle.load(f)

class PredictRequest(BaseModel):
    features: list[float]

class PredictResponse(BaseModel):
    prediction: int
    confidence: float

@app.post("/predict", response_model=PredictResponse)
def predict(request: PredictRequest):
    X = torch.tensor([request.features])
    with torch.no_grad():
        logits = model(X)
        probs = torch.softmax(logits, dim=1)
        pred = probs.argmax().item()
        conf = probs.max().item()
    return PredictResponse(prediction=pred, confidence=conf)

# 启动：uvicorn main:app --host 0.0.0.0 --port 8000
启动后，任何人都能通过 POST http://your-server:8000/predict 调用你的模型，传入特征，获得预测结果。FastAPI 自动生成交互式文档（/docs）。
◆ Docker：让部署可移植
# Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
# 构建并运行（在任何有 Docker 的机器上都能运行）
docker build -t my-ai-app .
docker run -p 8000:8000 my-ai-app
类比：集装箱
Docker 把你的应用、代码、依赖、配置全部打包成一个"集装箱"。无论在你的笔记本、测试服务器还是云服务器，这个集装箱打开来运行的效果完全一样——"在我电脑上能跑"的问题消失了。
▸ 部署后的监控：线上模型会"漂移"
数据漂移（Data Drift）
线上输入数据的分布随时间变化（如疫情期间用户行为突变），导致模型表现下降。
监控：定期比较线上数据分布与训练集的统计差异。
概念漂移（Concept Drift）
X→Y 的映射关系本身变化了（如"好"的标准变了）。即使数据分布没变，模型效果也下降。
监控：持续收集真实标签，定期重新评估模型。

AI Agent：让大模型自主完成多步骤任务

传统 AI：输入 → 模型 → 输出（一次性）。Agent：给模型一套工具，让它自己决定调用哪些工具、按什么顺序，完成复杂任务。

类比：AI 助理 vs AI 员工
传统 RAG/聊天机器人像"AI 助理"——你每次说一件事，它做一件事。Agent 像"AI 员工"——你说"帮我调研竞品并写报告"，它自己去搜索网页、整理信息、分析对比、最后写出报告。中间所有步骤它自己决定。
①
工具（Tools）

给 Agent 配备可调用的工具：搜索引擎、代码执行器、数据库查询、发送邮件、文件读写...每个工具有明确的输入输出定义。

②
规划（Planning）

Agent 收到任务后，先分解步骤，判断需要用哪些工具、按什么顺序。

③
执行 + 观察 + 调整（Act-Observe-Adjust 循环）

调用工具 → 观察结果 → 根据结果决定下一步 → 直到任务完成。

import anthropic

client = anthropic.Anthropic()

# 定义工具
tools = [
    {
        "name": "search_web",
        "description": "在互联网上搜索信息",
        "input_schema": {
            "type": "object",
            "properties": {
                "query": {"type": "string", "description": "搜索关键词"}
            },
            "required": ["query"]
        }
    },
    {
        "name": "calculate",
        "description": "执行数学计算",
        "input_schema": {
            "type": "object",
            "properties": {
                "expression": {"type": "string", "description": "数学表达式，如 '2 + 3 * 4'"}
            },
            "required": ["expression"]
        }
    }
]

# Agent 会自动决定调用哪个工具
response = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    tools=tools,
    messages=[{"role": "user", "content": "2024年中国 GDP 是多少？换算成美元大约是多少？"}]
)

# 检查是否调用了工具
if response.stop_reason == "tool_use":
    tool_call = response.content[-1]
    print(f"Agent 决定调用工具: {tool_call.name}")
    print(f"工具参数: {tool_call.input}")
Agent 的边界：Agent 越强大，风险越高。在生产环境中，工具调用权限要严格控制（Agent 不应该有删除数据库的权限），敏感操作需要人工审批，避免失控。

本章小结 · 全程总结

第五章核心要点
  • 提示词工程：RTCF 框架（角色/任务/约束/格式）写出好提示词；Few-shot 给示例；Chain-of-Thought 引导推理——这是大模型应用开发的核心技能。

  • AI Agent：给大模型配备工具（搜索/代码执行/数据库等），让它自主规划和多步骤执行复杂任务。生产环境需严格控制工具权限。
  • 作品集：三个层次（基础/进阶/旗舰）；每个项目必须有问题定义、数据说明、定量结果和可运行的 Demo。诚实展示局限比吹嘘更有说服力。

词汇表

提示词（Prompt）
用户或开发者输入给大语言模型的指令或问题。质量直接影响输出质量，提示词工程是大模型应用的核心技能。
少样本提示（Few-Shot Prompting）
在提示词中给出几个输入-输出示例，帮助模型理解任务格式和期望输出。适用于格式固定、模式重复的任务。
思维链（Chain-of-Thought）
引导模型逐步写出推理过程再给出最终答案的提示词技术，显著提升复杂推理任务的准确率。
RAG（检索增强生成）
在推理时从知识库检索相关文档，将其注入提示词作为上下文，让模型回答私有/最新知识的技术。
嵌入向量（Embedding）
把文字的语义压缩成高维数字向量。语义相近的文字向量也相近，是语义搜索和 RAG 的基础。
向量数据库（Vector Database）
专门存储和检索向量的数据库（如 Chroma、Pinecone），支持高效的相似性搜索，是 RAG 的核心基础设施。
FastAPI
Python 的高性能 Web 框架，用于将 ML 模型封装成 REST API，自动生成交互式文档（/docs）。
Docker
把应用及其所有依赖打包成可移植"容器"的工具，确保在任何机器上运行效果一致。
数据漂移（Data Drift）
线上输入数据的分布随时间变化，导致按旧数据训练的模型效果下降。需要持续监控并定期重新训练。
AI Agent
配备了工具调用能力的大模型，能自主规划任务步骤、调用工具（搜索/代码执行等），多步骤完成复杂任务。
